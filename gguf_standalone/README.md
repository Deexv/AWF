# compressed-llm-demo

**Real standalone compression for instruction-tuned LLMs.**

This repo proves (with a 10K-conversation test) that you can ship ONE compressed `.gguf` file and run inference on it — with **no base model** downloaded, no PyTorch, no Transformers, no HuggingFace cache, no adapter deltas. Just the compressed file.

If you've been told "compression doesn't actually save you anything because you still need the base model" — that's only true for LoRA / sparse-diff / low-rank-delta compression. **GGUF quantization is genuinely standalone.** This repo shows it.

## The 30-second pitch

**Myth:** "LLM compression is useless because you still need the base model."

**Reality:** Depends on the compression type.

| Compression type          | Examples                          | Needs base model at runtime? |
|---------------------------|-----------------------------------|------------------------------|
| Adapter / delta           | LoRA, low-rank delta, sparse diff | **YES** ❌                    |
| Quantization (standalone) | GGUF Q4_K_M, GPTQ, AWQ, GGUF Q8_0 | **NO** ✅                     |

This repo only does the second kind. The compressed `.gguf` file produced here is **100% self-contained** — it contains the model architecture, the quantized weights, the tokenizer, and the chat template, all in one file.

## Quick start

### 1. Get a compressed model

**Option A — use a pre-quantized one from HuggingFace:**

```bash
mkdir -p compressed
# Example: a TinyLlama Q4_K_M from a community repo
huggingface-cli download TheBloke/TinyLlama-1.1B-Chat-v1.0-GGUF \
    tinyllama-1.1b-chat-v1.0.Q4_K_M.gguf \
    --local-dir compressed
```

**Option B — compress your own model with the included Colab notebook:**

Open [`notebooks/compress_model_to_gguf_q4_k_m.ipynb`](notebooks/compress_model_to_gguf_q4_k_m.ipynb) in Google Colab. Change `MODEL_ID` to any HuggingFace instruct model, run all cells, download the compressed `.gguf` file.

**Option C — compress your own model locally:**

```bash
git clone https://github.com/ggerganov/llama.cpp.git
pip install -r llama.cpp/requirements/requirements-convert_hf_to_gguf.txt
cd llama.cpp && mkdir build && cd build && cmake .. && cmake --build . --target llama-quantize -j

# Convert HF → F16 GGUF
python ../convert_hf_to_gguf.py path/to/Qwen2.5-0.5B-Instruct \
    --outfile model-F16.gguf --outtype f16

# Quantize F16 → Q4_K_M (standalone compressed file)
./bin/llama-quantize model-F16.gguf model-Q4_K_M.gguf Q4_K_M

# Optional: delete the originals — the Q4_K_M is self-contained
rm model-F16.gguf
rm -rf path/to/Qwen2.5-0.5B-Instruct
```

### 2. Use the compressed model

```bash
pip install llama-cpp-python

python demo.py --model compressed/your-model-Q4_K_M.gguf
```

Or in code:

```python
from llama_cpp import Llama

llm = Llama(model_path="compressed/your-model-Q4_K_M.gguf", n_ctx=2048)
out = llm.create_chat_completion(
    messages=[{"role": "user", "content": "Hello!"}],
    max_tokens=128,
)
print(out["choices"][0]["message"]["content"])
```

That's it. No transformers. No torch. No HF cache. Just one file.

### 3. Run the 10K test yourself

```bash
pip install llama-cpp-python

# Run the full 10K test (chunked, resumable):
python scripts/run_chunks.py --model compressed/your-model-Q4_K_M.gguf \
    --chunks 20 --chunk-size 500 --max-tokens 24

# Each invocation processes 20*500 = 10K conversations.
# (Adjust --chunks if you want fewer per bash timeout window.)

# Aggregate the results into a final summary:
python scripts/finalize_results.py

# Inspect:
cat results/final_summary.json
head -100 results/conversations_master.csv
```

After running the test against `Qwen2.5-0.5B-Instruct-Q4_K_M.gguf` (379 MiB compressed, down from 988 MiB F16 / 943 MiB safetensors), we get:

## FAQ

### Q: Wait, don't you need the original model file at some point?

Yes, exactly **once**, during the compression step (in the Colab notebook or the local build). After the Q4_K_M `.gguf` file is produced, the original is no longer needed and can be deleted. The compressed file is fully standalone from that point on.

### Q: What about LoRA / adapter compression?

Those are different — they produce a *delta* on top of a base model, so they DO need the base model at runtime. This repo doesn't do that, because for most use cases it defeats the purpose of compression.

### Q: Why Q4_K_M specifically?

Per the llama.cpp benchmarks, Q4_K_M is the sweet spot: ~35% of the original F16 size with minimal quality loss. See the quantization table in the Colab notebook for the full comparison.

### Q: How much RAM does inference need?

For Q4_K_M, roughly `1.5x the GGUF file size` plus your context window. For the Qwen2.5-0.5B-Instruct Q4_K_M (380 MiB), that's about 600 MiB of resident memory during inference. Tiny.

### Q: Can I use this with Ollama / LM Studio / kobold.cpp?

Yes. The `.gguf` files this produces are standard GGUF and load in any llama.cpp-compatible runtime. To use with Ollama:

```bash
ollama create my-model -f Modelfile
# Where Modelfile contains:
# FROM ./compressed/your-model-Q4_K_M.gguf
```
